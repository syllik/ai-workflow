# ai-workflow context

This repository is the canonical GitHub-rooted storage for AI workflow rules, durable project context, decisions, and bounded task prompts. GitHub repository records live in `workspace.yaml`; legacy central project contexts remain preserved for migration and are outside the active reading path.

Commands:

- `npm test` runs the built-in `node:test` suite.
- `npm run verify` runs tests, manifest-only validation, generated-drift validation, and `git diff --check`.
- `node scripts/workspace/cli.mjs check --manifest-only` validates the manifest only.
- `node scripts/workspace/cli.mjs check` validates generated routing and budgets.
- `node scripts/workspace/context-producer.mjs < context-input.json` builds a task-scoped context manifest, authorizes expected sources before loading exact `repository@revisionSha:path` Git bytes via `repositoryRoots`, verifies caller bodies and requirement IDs, and derives versioned UTF-8 provenance. v1/unspecified uses the hard 32768-byte gate; explicitly allowlisted v2 uses `assembledContextBudgetBytes: null` plus trusted receipt, source-consumption, coverage, structure and integrity checks. Activation is pinned by `workspace.yaml` `contextPolicy` at `policySha`: the producer loads policy sources first, rejects a different caller policy, and loads `contextDependencies` only if that registry declares them. New tasks (`newTask: true`) default to v2 only for an allowlisted, non-excluded repository with Task Contract v2; otherwise v1. The v2 manifest binds `taskId`, approval reference and scope digest. `evaluateTaskAction()` takes coverage sets, digest and policy only from that trusted manifest, and the source verifier (`createTrustedSourceVerifier()`: Git loader plus runner delivery ledger) and runtime adapter only as trusted top-level inputs; receipt runtime claims are ignored. Resume (`recoverContextAdmission()`) re-runs `evaluateTaskAction()` with a fresh manifest; checkpoints carry an HMAC head record against rollback. In v2-allowlisted projects, document length budgets except `AI.md`/`FLOW.md` are advisory.

The integration branch is `master`. Active entrypoints, README bootstrap and reusable prompts must assign work by canonical role, not mandate a provider/model. Named integrations such as GitHub Codex review are optional adapters, not exclusive role owners; independence and trust boundaries still apply. Current task-policy contract is v2: provider-independent roles plus a separate Trusted Publisher; legacy v1/unspecified handoffs retain human-gated publication/corrections. Context Policy v2 remains disabled by default and never reinterprets a pinned v2 handoff as v1 after rollback. Changes are published only through an authorized task branch and PR into `master`; `npm run verify` is the completion gate. Real canonical workspace apply remains subject to normal safety checks. Routing rollout is verification-only: it checks generated managed consumers plus explicitly required read-only context at exact Git SHAs and never publishes rules into consumers.
