# Global core

- GitHub is the only project registry; use `workspace.yaml` and never auto-discover repositories.
- Resolve target repository instructions from the selected record's `integrationBranch`. Active managed projects may receive normal work; onboarding managed projects are limited to onboarding/alignment until their routing/context exists.
- `contextDependencies` are explicit approved read-only context sources, not write targets or repository-discovery hints. Read them only when target instructions or task scope requires them; if required context is unavailable, block instead of guessing.
- Read the smallest relevant context in the order defined by `FLOW.md`.
- Preserve target-repository rules and user scope. Do not store secrets, credentials, tokens, private keys, `.env` content, or conversation dumps.
- `read-only` projects are never write targets. Managed updates require valid `ai-workflow` markers and a clean, single-worktree repository.
- New projects and repositories require an explicit licensing decision before the first commit, regardless of public/private visibility. Sol must ask the human, explain practical license choices and the consequences of proprietary/no-license options, and ensure the selected `LICENSE` or rights notice is created with the bootstrap template. Forks and derivatives must preserve upstream licenses/notices and must not be relicensed incompatibly.
- A net-new tool requires current reuse research before implementation. Check maintained analogues, libraries, services, and forkable projects plus their licenses; prefer reuse or a legally and technically viable fork with the smallest necessary delta. Greenfield implementation requires a recorded reason why reuse or forking is unsuitable.
- Adding a project to `workspace.yaml` requires a coordinated `syllik/syllik` change for `docs/workspace.md` and `docs/repositories.md`. The registry change is not ready for human merge until that workspace-documentation change exists and is synchronized with it. The profile `README.md` is a stable link to the workspace page, not a duplicated project list. Omission from workspace documentation requires an explicit human decision.
- Routine PR review uses managed Codex GitHub Code Review. Codex automatic PR review is disabled: opening a PR, marking it Ready, or pushing a new head must not automatically start review. The only routine trigger is an explicit `@codex review` PR comment after the repository-defined full CI gate for the current PR head is complete and green. Never trigger review while CI is pending or failing, and never duplicate a review already running or current for the same head. A review is current only when its reviewed commit SHA matches the current PR head. Any head change invalidates prior CI/review evidence and requires fresh full green CI followed by a new `@codex review` comment. Codex is reviewer-only; never use `@codex fix`, `@codex address that feedback`, or any other branch-mutation command. Sol 5.6 High is escalation/fallback only. Findings reach Luna only after explicit human authorization, and only a human merges.
- Generated files are deterministic, LF-only, and end with one newline. Drift and hard-budget violations block completion.
