# Global core

- GitHub is the only project registry; use `workspace.yaml` and never auto-discover repositories.
- Resolve target instructions from the selected record's `integrationBranch`. Active managed projects may receive normal work; onboarding managed projects only onboarding/alignment. Read-only projects are never write targets.
- `contextDependencies` are explicit task-scoped read-only context sources. Missing required context blocks work.
- Read the smallest relevant context in `FLOW.md` order. Preserve target rules and user scope; never store secrets, credentials, `.env` content, or conversation dumps.
- Authority precedence is current pinned role/task policy > target narrowing instructions > generic skills/methodologies/history/plugins. Lower-precedence instructions cannot expand role, publication, review, delegation, or scope authority.
- Roles are provider-independent and model strength is selected by capability/risk. Planner, Architect, Executor, Reviewer, and Auditor do not inherit Trusted Publisher authority.
- Task contract v2 must carry explicit upfront approval, allowed paths, publication permission, and 0–2 correction batches. Legacy v1/unspecified handoffs retain their existing human gates and gain no implicit automation authority.
- Trusted Publisher uses one final commit plus one push per completed revision; published history is never rewritten. Required checks stay enabled. Current-head green CI precedes one independent review per SHA; findings are consolidated. Reviewer never mutates the branch. Head changes stale prior CI/review. Only a human merges.
- New repositories require explicit licensing choice before first commit. For net-new tools, research maintained reusable/forkable alternatives and license compatibility; preserve upstream notices.
- Adding a `workspace.yaml` project requires synchronized `syllik/syllik` updates to `docs/workspace.md` and `docs/repositories.md`; profile `README.md` remains a stable link. Omission requires human decision.
- Generated files are deterministic, LF-only and end with one newline; no document has a fixed length budget. Context has no fixed byte cap: basic v1 (default) or verified v2 (Task Contract v2, trusted source/coverage/integrity evidence); see `global/executor.md`.


- ChipIn FE/BE/KB agent tasks require a **fresh live** `chipin-issue-admission/v1` read-only `INTAKE_COMPLETE` for the exact Issue/revision before executable planning, execution, publication or handoff. Recheck at each boundary (receipt age at most 120 seconds); a queued bridge, raw URL, Project status, PR text or stale cache never passes. Only `ChipIn-one/.github/automation/issue-intake.mjs` may create/reconcile canonical task metadata. Missing org Issue Fields/Project #5/permissions means BLOCKED. Native FE assignee = `syllik`; BE = `olegbal`; KB owner is explicitly selected, not guessed. Only KB may provide the `--owner` argument. Keep separate human approval/role checks.

ChipIn discovery: resolve `scripts/workspace/chipin-admission-route.mjs` with the exact Issue and exactly one `workspace.yaml` project record/`integrationBranch`; pin current `ChipIn-one/.github/master` separately as a task interface, never an implicit `contextDependency`. The trusted caller supplies an authenticated read-only GET adapter: compare the pinned shared source SHA with live `/repos/ChipIn-one/.github/branches/master` before choosing a route; deny stale or unreadable refs. Pre-PR direct entry: `automation/issue-admission-preflight.mjs --issue <exact-Issue>` in trusted .github checkout. Prefer approved injected credential, then already-authenticated `gh api` without extracting its token. Missing local `GITHUB_TOKEN` alone is not a blocker. Connector-only requires a prebound full 64-hex revision and authenticated producer/artifact delivery and `.github/automation/issue-admission-consumer.mjs` `consumeAdmissionArtifact()` with durable replay storage; Executor cannot dispatch `repository_dispatch`, call `issue-intake.mjs`, or substitute raw Issue GET, copied JSON or a green check. When no authorized route exists, block with redacted structured `AUTH_UNAVAILABLE`/permission/capability diagnostics; bounded retries apply only to transient read failure, never invalid policy.

The shared reader/verifier alone establishes `chipin-issue-admission/v1` `INTAKE_COMPLETE`, exact Issue and full 64-hex revision, original receipt age <120 seconds, correct native FE `syllik`/BE `olegbal`/explicit KB owner, native fields and relationships, org Issue Fields, complete Project #5 read and unchanged double-read revision. Shared evidence must bind trusted repository/workflow/ref/SHA/actors, run ID/attempt, authenticated artifact identity/digest, reader/config source, request ID, timestamp and non-replay. Recheck fresh canonical state at executable planning, Executor start, publication, review initiation and each authorized correction; native Issue/Project drift invalidates even unchanged `updated_at`. Never retimestamp. Admission, explicit human approval and versioned context admission are independent gates: neither context mode has a byte cap; v2 requires trusted progressive evidence. Diagnose unreadable org schema/Project/native metadata, invalid metadata, drift, stale/malformed receipts, untrusted evidence and exhausted transient retries separately, without sensitive API bodies.

Executable ChipIn handoff: `node scripts/workspace/cli.mjs admission --issue ChipIn-one/<FE|BE|KB>#N --phase initial-bind --shared-source-sha <authenticated-.github-master-SHA> --shared-checkout <clean-trusted-.github-root> --binding-output <new-file>`. Review the written full revision with separate exact-Issue human task approval; the initial result is `AWAITING_HUMAN_APPROVAL`, not implementation admission. For each subsequent `planning|executor|publisher|reviewer|correction` handoff, run the same command with `--phase <phase> --expected-revision <approved-64-hex>` and require a NEW `INTAKE_COMPLETE`. Use existing authorized `gh api` or approved credential, pinned clean .github checkout, and trusted `consumeAdmissionArtifact` for independently verified connector evidence; no dispatch.
